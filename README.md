# Rank-reversal-aware calibration of PROMETHEE II

Code, data and results of the article *Rank-reversal-aware calibration of PROMETHEE II*
(Y. Omari, S. Reguieg), submitted to *Computers & Operations Research*.

PROMETHEE II returns a complete ranking even when the pairwise preferences behind it conflict.
One visible consequence is rank reversal: the order of two alternatives changes when another
alternative is removed or added. This repository implements a method that keeps PROMETHEE II
unchanged and selects, among the parameters the decision maker finds acceptable, those whose
ranking depends least on the other alternatives.

## What the method does

**Input.** A decision matrix, the elicited parameters (weights, or only their order of
importance, and preference functions) and a tolerance, the share of weight that may move.

**Process.**
1. *Diagnosis.* The conflict of the elicited ranking is measured exactly: reversal rate and
   fragility under the deletion of one alternative (Theorem 1, without re-ranking), cyclicity
   (Theorem 2) and incomparability.
2. *Search.* NSGA-II explores the admissible parameters, encoded so that every candidate keeps
   the stated order of the weights (Proposition 2).
3. *Certification.* A mixed-integer model, pruned by stability radii (Lemma 1), returns the
   optimal weights for a given budget and proves their optimality (Proposition 3).
4. *Selection.* The least-conflict model within the tolerance, or the knee of the front.

**Output.** The calibrated parameters, the trade-off between conflict and deviation, and the
pairwise conclusions of the elicited ranking that are fragile.

## Minimal example

```bash
cd code
pip install -r requirements.txt
python example.py
```

```python
import numpy as np
from gpii.data import load
from gpii.core import promethee
from gpii.conflict import conflict_measures
from gpii.calibration import Calibration
from gpii.moea import run
from gpii.exact import solve_eps

d = load("ELECTRIC")                                    # decision matrix and elicited model
print(conflict_measures(promethee(d.X, d.model).P))     # 1. diagnosis of the elicited ranking

cal = Calibration(d.X, d.model, measure="event_rate", scenario="W")   # keep the order of the weights
evo = run(cal, "NSGA-II", budget=3000, pop=50, seed=0)  # 2. evolutionary front
ex = solve_eps(cal, 0.02)                               # 3. certified optimum for a budget of 0.02
X, F = evo["X"], evo["F"]
if ex["status"] == 0:
    X, F = np.vstack([X, ex["x"]]), np.vstack([F, ex["F"]])

ok = np.flatnonzero(F[:, 1] <= 0.02 + 1e-9)             # 4. least reversal rate within the budget
best = ok[np.argmin(F[ok, 0])]
model = cal.decode(X[best])
print("relative reversal rate", F[best, 0], "deviation", F[best, 1])
print("calibrated weights", np.round(model.w, 3))
```

On the electric-vehicle benchmark this removes every single-deletion reversal by moving 2% of
the weight, in about five seconds on a laptop. Your own data are passed as a matrix `X`
(alternatives in rows) and a `gpii.model.Model` holding the weights, preference-function types,
thresholds and criterion directions.

## Repository layout

```
code/
  gpii/           package: preference functions, PROMETHEE, conflict measures, exact reversal
                  counting, calibration, evolutionary search (pymoo), exact MILP (HiGHS via SciPy)
  experiments/    one script per experiment of the paper, and the scripts that write the tables
  tests/          162 tests; the theoretical results are checked numerically and symbolically
  example.py      the minimal example above
data/
  public/         public benchmarks with provenance and licences (data/public/README.md)
  electric_v_selection.xlsx   electric-vehicle benchmark
results/          raw CSV results and logs of every experiment
paper/
  tables/         every table body and number macro of the paper, as generated by the scripts
  figures/        every figure of the paper
  figures_src/    TikZ sources of Figures 1 and 8
run_all.sh        reproduces everything from the raw data
```

## Reproducing the paper

```bash
bash run_all.sh            # about 6 h on two cores
```

| Experiment | Command (from `code/`) | Output |
|---|---|---|
| Tests | `python -m pytest tests -q` | |
| Benchmarks: diagnosis, search methods, exact optimum, fronts, validation | `python -m experiments.run_calibration --workers 2` | `results/calibration` |
| Random elicited models (225) | `python -m experiments.run_robustness --draws 45 --workers 2`, then `--tables` | `results/robustness` |
| Baselines from the literature | `python -m experiments.run_baselines --workers 2` | `results/baselines` |
| Ties, certification, sensitivity analyses | `python -m experiments.run_revision --workers 2` | `results/revision` |
| Statistics with Holm correction | `python -m experiments.revision_stats` | `results/revision/stats_*.csv` |
| Synthetic benchmark (216 instances) | `python -m experiments.run_synthetic --workers 2` | `results/synthetic` |
| Wall-clock time of each stage | `python -m experiments.run_timing --workers 1` | `results/revision/timing.csv` |
| Empirical scaling | `python -m experiments.run_scaling` | `results/revision/scaling_*.csv` |
| Side effects and larger budgets | `python -m experiments.run_sideeffects` | `results/revision/sideeffects.csv` |
| Literature-based indicators | `python -m experiments.run_litmeasures` | `results/revision/litmeasures.csv` |
| Tables and figures | `figures_cal`, `figures_cor`, `cor_tables`, `revision_tables`, `baselines_tables` | `paper/` |

All random seeds are fixed in the scripts. The exact model is solved by HiGHS through
`scipy.optimize.milp` with default parameters except the time limit and a zero relative gap.
Exact package versions are in `code/requirements-lock.txt` (Python 3.13).

**Hardware.** The wall-clock times reported in the paper (`timing.csv`, `scaling_*.csv`) were
measured on one core of a laptop with an Intel Core i7-11800H (Windows 11, Python 3.9), with
`code/run_timing_laptop.bat`; the machine is recorded in `results/revision/hardware_*.txt`.
All other experiments ran on one core of a two-core Intel Xeon virtual machine; earlier timing
measurements on that machine are kept in `results/revision/cloud/`.

## Data

All benchmarks are public: Human Development Index 2023, World Happiness Report 2024, OECD
Better Life Index 2017, ASEM Sustainable Connectivity and a published electric-vehicle
selection problem. Sources, versions and licences are listed in `data/public/README.md`. The
data remain under the terms of their original providers.
